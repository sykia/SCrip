# Recommendations

SCrip orders SoundCloud related-track results locally; it does not train a model
or promise recommendation accuracy. The implementation uses only the documented
`GET /tracks/{track_urn}/related` endpoint (`limit`, `linked_partitioning`).
Sources checked on 2026-11-16:

- [Official OpenAPI specification](https://github.com/soundcloud/api/blob/master/openapi/api.yaml)
- [Official rate-limit documentation](https://developers.soundcloud.com/docs/api/rate-limits)

## Sources and budgets

Home selects up to three playable liked tracks with different artist URNs from
the available first likes page (not just the 24 liked-mix entries). Each source contributes at most 40 candidates in
one request. It does not paginate to fill a shelf. Empty and failed sources do
not hide successful sources. Concurrent identical reads are shared by the
existing account-scoped request coordinator. Background quota handling and
bounded transport retries apply; there are no new quota estimates or bypasses.

Discovery wave rotates its saved frontier and selects up to three distinct-artist
sources per batch. Results are interleaved by source and service rank, independent
of response completion order. Multi-source batches use the first page only;
single-source/restored cursors retain pagination. An empty refill spends at most
six related requests before the existing bounded retry/backoff policy takes
over (at most three automatic retry timers). Successful additions reset backoff.
Liked-track pagination and the saved frontier remain available to expand sources.
Artists without user URNs cannot reliably be grouped; names are not identities.

## Ordering and shelves

Track URNs identify duplicates. Home excludes its available liked source tracks,
then selects at most 48 candidates and balances entries by shelf size and artist counts between “You might
like” and “Discovery mix”, at most 24 each, without overlap. Short results stay
short; a one-track pool only produces one recommendation shelf. “Liked mix”,
releases and listening history remain independent existing blocks.

Selection prefers unused artists, then avoids adjacent artists, then permits
artist repeats if necessary. Blocked, explicitly unstreamable, invalid and
excluded track URNs never become eligible through this relaxation. Wave also
excludes its complete saved set of queued track URNs and current manual queue. The existing
library-wave shuffle remains enabled.

`recommendationSource` and `recommendationSourceUrn` record the contributing
seed, not an explanation generated by a model. Home subtitles and the wave
control tooltip/accessibility description expose a short “Similar to …” label.
Android uses the existing muted caption style for home subtitles.

## Playback and cancellation

Batches capture the home/wave generation and check it before publishing results.
They never replace a queue or choose a track directly. Wave appends through the
existing refill path, preserving navigation, manual entries, paused state and
saved sessions. Manual history selection cancels the waiting-to-autostart flag,
so an already pending refill can append without overriding that selection. Clearing after the current track invalidates pending wave work
even when there are no upcoming entries yet. Changing modes, stopping playback,
signing out and other existing queue-edit invalidations discard stale results.

Deterministic transport tests cover source limits, shared reads, completion order,
partial failures, URN duplicates, availability, artist relaxation, short disjoint
shelves, exhaustion budgets and stale wave replies after queue clearing. No test
asserts subjective recommendation quality. Availability and relevance remain
limited by the service catalogue and returned metadata.

## Local preferences and exclusions

The wave exposes Familiar, Balance and Discovery preferences directly as three
inline segments on desktop and Android. These preferences affect only
future discovery-wave batches. For each bounded batch (at most 20 tracks), local
selection follows respectively two familiar then one new, alternating familiar
and new, or one familiar then three new. These are ordering rules, not promised
percentages for Familiar and Balance: exhausted pools fall back to available eligible
candidates. Discovery permits at most one familiar track per three new candidates
and leaves the batch short when new candidates run out. Related results marked as
liked by the synchronized library or current like overrides are never counted as new. Familiar
tracks come from at most 200 already fetched liked tracks, saved with the wave;
new candidates come from the existing related-track requests. No additional
request or pagination loop is introduced to satisfy a mix. All three segments use
the discovery engine; the legacy library backend remains available for saved-session
compatibility. Selecting an inline preference rebuilds only upcoming automatic
entries and starts a different eligible track. The previous track remains in
history and manual additions stay queued. Up to 120 related candidates from the
latest response are saved with the wave for local reselection. If there are no
eligible local candidates, the current audio continues until the bounded refill
returns; pausing or manually selecting a track cancels that pending transition.
The storage-only setter remains available without a playback side effect.

Track exclusions use track URNs. Account exclusions use the uploader's user URN,
never metadata artist text or a display-name comparison. The menu explicitly
names the uploading account because a label's uploads cannot reliably identify
an individual credited musician. Likes, follows, search, explicitly opened
collections and manual playback remain unchanged.

Only recommendation shelves and future entries marked as automatic
recommendations are pruned, including restored entries and replies received
after an exclusion. Explicit enqueue operations strip automatic provenance and
save a manual marker. Unknown legacy queue provenance is conservatively retained
to preserve manual additions. The current entry and playback history remain
available. Removing a future automatic entry cancels any prepared successor and
crossfade, preserving the active player before preparing another successor.
Undo removes only the latest newly added exclusion; repeating an existing
exclusion cannot undo an older one. Undo restores eligibility, without rebuilding
a queue or replaying already removed shelf entries.

Preferences and named exclusions use platform QSettings outside the repository,
under separate SoundCloud user URNs. Missing profiles disable mutations; malformed
JSON and invalid entries are ignored. Account changes clear undo and invalidate
home/wave generations, so previous replies cannot publish into the new account.
Settings offer searchable Tracks and Accounts sections, individual restoration,
and a confirmed reset from an additional menu.
