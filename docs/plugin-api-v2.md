# Plugin API v2: архитектурное решение

Статус: спецификация этапа 2, 08.11.2026. Это контракт для реализации этапа 3, а не описание уже работающего API. Сейчас работает только v1 из [plugins.md](plugins.md). Следующая команда «Продолжай» разрешает начать реализацию этого решения; отдельного подтверждения архитектуры не требуется.

## Решение и граница доверия

Основной формат v2 — один JSON-файл UTF-8 без архива, ресурсов и исполняемого кода. C++ валидирует документ, строит типизированное внутреннее представление и исполняет только конечный набор операций. QML отображает данные штатными компонентами приложения. Нельзя загружать из пакета QML, JavaScript, HTML, библиотеки, процессы, произвольные URL, пути, регулярные выражения или выражения для вычисления.

Различаются `kind: declarative` и `kind: executable`. Первая реализация принимает только declarative; executable возвращает `unsupported-runtime` при установке, включая платформу и причину. Приложение не объявляет поддержку executable и не устанавливает его как якобы рабочий плагин. Ни QJSEngine, ни отдельный обычный QProcess не считаются надёжной изоляцией. Qt прямо описывает JavaScript sandbox как семантическую границу, а модель доверия — как для C++: [Making Applications Scriptable](https://doc.qt.io/qt-6/qtjavascript.html).

Будущий executable backend требует отдельного архитектурного решения: отдельный процесс, платформенная изоляция файлов/сети/процессов, ограничения памяти и CPU, версионированный IPC без QObject и токенов, принудительная остановка и отрицательные тесты на каждой поддержанной платформе. До этого он закрыт на всех платформах. Подпись пакета сама по себе не даёт изоляции.

Угроза: вредоносный JSON может пытаться исчерпать ресурсы, получить данные, управлять плеером без согласия или подменить UI. Пользовательские программы с доступом к файлам SCrip находятся вне этой модели. Полномочия контролируются хостом при каждой операции, а не только видимостью кнопок.

## Манифест и совместимость

Обязательные поля: `api: 2`, `kind`, `id`, `name`, `version`, `requiresHost`, `permissions`, `settings`, `contributions`, `rules`. Необязательные: `description`, `dependencies`. Неизвестные поля, повторяющиеся JSON-ключи, неверные типы и превышение лимитов отклоняются. Для дубликатов ключей необходима проверка до QJsonDocument: после разбора они уже потеряны; использовать ограниченный JSON-токенизатор для этой проверки, без нового интерпретатора.

- `id`: существующий шаблон v1, 1–48 символов. Это идентификатор, а не путь.
- `name`: 1–48, `description`: до 1000 печатных символов. Весь текст выводится как PlainText; ссылки и rich text не интерпретируются.
- `version`: три неотрицательных целых `major.minor.patch`, каждое до 65535, без префикса, prerelease и build suffix. Сравнение числовое.
- `requiresHost`: `{ "min": "1.4.1", "maxExclusive": "2.0.0" }`; обе границы обязательны, min < max. API выбирается отдельно числом api. Поддержанные API первой реализации — 1 и 2.
- `dependencies`: до 8 обязательных зависимостей `{id,min,maxExclusive}` с теми же версиями. Только установленные v2; v1 не имеет версии и не удовлетворяет зависимость. Нет автоматического скачивания, самозависимостей и циклов. Нет вызовов и доступа к данным другого плагина.
- Идентификаторы settings, contributions, rules уникальны в своём разделе и стабильны между обновлениями: `[a-z][a-z0-9.-]{0,47}`. В ссылках используется ID, а не индекс.

Лимиты: 128 КиБ входного файла, глубина JSON 16, 24 установленных плагина всего с v1, 16 настроек, 8 вкладов UI, 16 правил, 4 условия и 4 действия в правиле, 4 кнопки панели. Все числовые значения конечны; целочисленные поля не принимают дроби, строки и bool. Каталоги зависимостей и лимиты проверяются до активации.

Пример предлагаемого формата (не устанавливается текущим v1):

```json
{
  "api": 2,
  "kind": "declarative",
  "id": "sleep-timer",
  "name": "Таймер сна",
  "version": "1.0.0",
  "requiresHost": {"min": "1.4.1", "maxExclusive": "2.0.0"},
  "description": "Приостановить музыку через выбранное время",
  "permissions": ["ui.panels", "player.control", "timers"],
  "settings": [{"id": "minutes", "type": "integer", "label": "Минуты", "default": 30, "min": 1, "max": 180}],
  "contributions": [{"id": "sleep", "type": "panel", "slot": "player.tools", "title": "Таймер сна", "buttons": [
    {"label": "Запустить", "action": {"command": "timer.start", "timerId": "sleep", "minutesSetting": "minutes"}},
    {"label": "Отменить", "action": {"command": "timer.cancel", "timerId": "sleep"}}
  ]}],
  "rules": [{"id": "pause", "event": "timer.expired", "conditions": [{"field": "timerId", "equals": "sleep"}], "actions": [{"command": "player.pause"}]}]
}
```

Настройка содержит id, type, label, default; integer также min/max, enum — options (до 16 уникальных строк длиной до 48). Поддержать boolean, integer и enum; свободный текст и секреты в первой версии отсутствуют. Вклад panel содержит id, type, slot, title, необязательные text/buttons/enabledSetting. Вклад theme содержит id, type, values и необязательный enabledSetting. enabledSetting ссылается только на boolean-настройку; значение по умолчанию применяется при отсутствии пользовательского. Один theme на плагин, порядок полей JSON значения не имеет. Все ссылки проверяются при установке; неизвестный слот, тип настройки или имя команды — ошибка, а не молчаливое игнорирование.

## Хост и жизненный цикл

Расширить существующий Plugins; отделить валидатор/типизированные описания и dispatcher команд, не создавать универсальный framework. Player adapter получает SoundCloud в C++ через явную привязку в main.cpp. QML получает только модель менеджера, нормализованные вклады и методы пользовательских действий. Не передавать sc, QNetworkAccessManager или произвольные QObject расширению.

Предлагаемый фасад Plugins: prepareInstall(QUrl) асинхронно возвращает preview с непрозрачным operationId; commitInstall(operationId, acceptedPermissions) принимает только подготовленный неизменяемый кандидат. Preview содержит различия версии/настроек/полномочий и срок жизни 5 минут. В нём фиксируется registryRevision: после изменения реестра commit требует новый preview. cancelInstall(operationId) отменяет операцию. setEnabled(id,bool), setPermission(id,name,bool), setSetting(id,key,value), remove(id,keepData), clearData(id) возвращают структурированный результат. installed/panels/theme остаются для совместимости v1; в модель installed добавляются версия, status, reason, requested/granted permissions и lastError. Подготовленные операции ограничены двумя на менеджер; истечение/отмена освобождает память. UI не передаёт путь хранения, нормализованный manifest или содержимое команды обратно хосту.

Состояния: `disabled`, `awaiting-permissions`, `blocked` (версия/зависимости), `active`, `error`. Установленный документ может быть сохранён disabled при недостающей зависимости; структурно неверный и неподдержанный runtime не устанавливаются. Сохранять отдельно desiredEnabled и фактическое состояние. При старте активировать топологически, при отключении — зависимые первыми. В UI показывать конкретную цепочку причины. Включение зависимости требует отдельного пользовательского действия; её разрешения не выдаются транзитивно.

Отключение немедленно снимает UI/оформление, подписки, таймеры и задания. Каждая работа несёт pluginId и generation; после смены generation результат игнорируется. Отключение не отменяет уже выполненную паузу/перемотку и не возобновляет музыку автоматически. Настройки сохраняются. Ошибка отдельной команды отображается без отключения; нарушение квот переводит в error до явного повторного включения. При logout отменять таймеры и очереди команд, обновлять доступность без передачи идентичности аккаунта.

## Разрешения

Запрошенный набор ограничен таблицей. Все разрешения обязательны для активации данного пакета; отказ сохраняет awaiting-permissions. Установка не включает плагин. Отзыв любого разрешения прекращает выполнение до повторного согласования. Проверять разрешение и активное состояние при каждом событии, действии и записи данных.

| Разрешение | Возможность |
| --- | --- |
| ui.panels | Штатные панели и кнопки в поддержанных слотах |
| ui.theme | Только accent, covers, coverRadius с пределами v1 |
| player.observe | Ограниченные снимки и события плеера |
| player.control | Пауза, возобновление, следующий/предыдущий, seek, repeat, shuffle |
| navigation | Переходы likes, history, feed, playlists, profile, search |
| storage | Собственный ограниченный key/value JSON |
| timers | До двух собственных одноразовых таймеров |

Настройки, заданные манифестом, хост хранит без отдельного storage: это пользовательская конфигурация. Нет разрешений на сеть, OAuth, файловую систему, shell, произвольные треки, загрузки и открытие внешних URL. Запрос неизвестного разрешения — ошибка установки. Наличие player.control не даёт player.observe.

## События, правила и команды

Хост не экспортирует общий sc.state. `player.observe` разрешает `player.trackChanged` (URN, название, исполнитель, длительность), `player.playbackChanged` (playing/buffering), `player.progress` (позиция, длительность), `player.queueChanged` (только число и индекс). Нет URL потоков/изображений, профиля, токенов, содержимого всей очереди и истории. Начальный снимок передаётся при активации; прогресс только по подписке, максимум раз в секунду. Идентификаторы и названия — персональные данные, это объясняется в диалоге разрешений.

Правило: event + до четырёх conditions + actions. Все условия объединяются AND; только equals для полей конкретного события с точным типом. Нет шаблонов, eval, вложенных правил и универсального выражения. `timer.expired` содержит только свой timerId и требует timers, а не player.observe. Вклад кнопки вызывает только проверенное действие своего плагина. Само включение не исполняет команды; начальный снимок не считается событием правила.

| Команды | Проверка |
| --- | --- |
| player.pause, player.resume, player.next, player.previous | player.control; соответствующая доступность плеера |
| player.seek {positionMs} | player.control; целое ≥0; seekable и ограничение длительностью |
| player.repeat / player.shuffle {enabled} | player.control; строго bool, без toggle |
| navigation.open {destination} | navigation; только перечисленные назначения |
| timer.start {timerId,minutesSetting}, timer.cancel {timerId} | timers; объявленная integer-настройка 1–180 минут; ID встречается в rules; повторный start заменяет свой таймер |
| storage.set {key,value}, storage.remove {key} | storage; литерал JSON, ключ из ограниченного ID-шаблона |

timer.start разрешён только явным нажатием кнопки, не правилом. Остальные действия допустимы в правилах при наличии разрешений; navigation.open — только нажатием, чтобы фоновые события не меняли страницу. storage пока хранит литералы и не является языком программирования; чтение доступно только в штатном просмотре данных менеджера, не через подстановки в команды. Полезное состояние таймера хранит хост отдельно и показывает в player.tools. После перезапуска таймеры не восстанавливаются. При уходе Android в сон пауза выполняется при ближайшей возможности event loop; точное время не обещается, AlarmManager/фонового сервиса в этом контракте нет.

Dispatcher: allowlist команд с отдельной проверкой аргументов и полномочий. Источник команды — созданный хостом контекст pluginId/generation, его нельзя брать из payload. UI передаёт ID вклада/кнопки, а не произвольную команду. Результат содержит requestId, ok, code и локализованное message; возможны permission-denied, inactive, unavailable, invalid-argument, rate-limited, storage-error. Нет вызовов QMetaObject::invokeMethod по строке из пакета.

Не выполнять правила рекурсивно в сигнале SoundCloud. Очередь не более 32 событий на плагин; progress схлопывается, переполнение других событий вызывает error. Причинная цепочка команд → событий несёт глубину (максимум 4); дальнейшие действия подавляются с ошибкой, а не продолжаются новым бесконечным циклом. На плагин максимум 8 действий/секунду с burst 8, на всех — 64; превышение повторных действий переводит виновный плагин в error. Общий лимит шага обработки — 8 действий с продолжением через event loop. Эти пределы должны иметь тесты; цифры являются бюджетом проекта, не результатами профилирования.

## Хранение, установка и обновление

Один `plugins-v2.json` в AppDataLocation: registryRevision, порядок установки, нормализованный манифест каждого пакета, версия формата реестра, desiredEnabled, grants, значения settings по ID, флаги групп v1, собственные data. Запись через QSaveFile: сначала полностью проверить кандидат, затем commit, затем заменить состояние в памяти и применить вклады. При ошибке записи не менять активную версию и настройки. Ограничение data — 256 КиБ на плагин, ключей 128, значения глубиной до 8; общий реестр до 16 МиБ. Квота учитывает сериализацию UTF-8. Манифест не выбирает пути. Работа с выбранным файлом и валидация ограниченного ввода выполняются вне GUI thread; итог публикуется на GUI thread, конкурентные операции сериализуются по revision.

v1 продолжает приниматься старым валидатором и адаптируется без новых разрешений: только прежние оформление и навигация. Индексы флагов v1 остаются индексами; для v2 — стабильные ID. При первом запуске без v2-реестра однократно импортировать валидные строки plugins-v1.json, сохранив порядок, enabled и flags; исходник оставить нетронутым. Если запись v2 не удалась, продолжить чтение v1 и показать ошибку миграции; не разрешать изменения до успешного сохранения. При существующем повреждённом v2 не откатываться молча к v1: оставить плагины неактивными и предложить явное восстановление. v1-файл не синхронизируется назад; downgrade приложения не обещает видеть новые изменения.

Обновление — выбор локального JSON с тем же id и большей version; v1 без версии можно заменить на v2 только с явным предупреждением и новым согласованием разрешений. v1→v1 замена подтверждается отдельно, flags сохраняются лишь при полном совпадении массива groups; иначе сбрасываются с предупреждением. v2→v1 и downgrade отклоняются. Показывать старую/новую версии, разрешения и изменения настроек до подтверждения. Сохранять типосовместимые settings по ID; неверные относительно новых пределов значения заменять defaults, перечисляя изменения в preview. Удалённые настройки не терять: хранить в ограниченном orphanSettings, который учитывается в квоте data; при возврате ID восстанавливать только совместимое значение. Данные не мигрируют скриптом. Если пакет не укладывается в квоту — отказ без частичного изменения.

Новые разрешения не выдаются автоматически: пользователь выбирает обновление и согласование либо оставляет старую версию. На время commit/замены остановить старые задания; после успеха создать новую generation. Неудача дисковой записи сохраняет старую активную версию. Обновление зависимости, которое ломает диапазоны зависимых плагинов, блокируется с перечислением зависимых; пользователь может сначала отключить их. Удаление зависимости требует явного согласия на отключение зависимых. При удалении спросить, сохранить ли конфигурацию/данные для переустановки; сохранённые записи видны и удаляемы в менеджере, учитываются в общем лимите 24 и квотах.

Совпадение id не доказывает автора: пакеты не подписаны. Preview локального обновления явно предупреждает об этом; SHA-256 файла показывается как контрольная сумма, не как доверие к издателю. Автопоиск и загрузка обновлений, магазин и криптографическая идентичность не входят в v2 первой реализации. Кнопка обновления честно называется «Обновить из файла».

Источник установки: file:// без удалённого host на desktop; на Android также content:// из системного picker. Не превращать content URI в локальный путь и не требовать QFileInfo::isFile. Читать ограниченный поток через Qt Android content file engine, при необходимости через узкий JNI ContentResolver.openInputStream; проверять ошибки/отзыв разрешения и фактический размер чтения, включая неизвестную длину. Скопировать прочитанные байты в реестр, не хранить URI/долговременный grant. Ограничение распространяется и на медленный provider; отмена помечает generation, а блокирующее чтение не должно удерживать GUI. Повторные импорты не создают неограниченное число worker threads. См. ограничения [QFile на Android](https://doc.qt.io/qt-6.8/qfile.html) и [Qt Android storage](https://www.qt.io/blog/qt-for-android-storage-updates).

## UI и оформление

Одинаковые слоты desktop/Android: home.panels, profile.panels, player.tools. Каждый panel имеет title (48), text (1000), до четырёх кнопок (label 32). Только штатные QML-компоненты, перенос текста, клавиатура/скринридер, вертикальная компоновка на узком экране. Виджет вкладов получает ограниченные данные, без произвольного Loader. Отсутствие места не меняет доступность команды. Скрытый слот не выполняет действий сам.

Тема v2 — один вклад type=theme с набором accent/covers/coverRadius в пределах v1. Приоритет: явно выбранное пользователем оформление → последний включённый вклад в порядке установки → стандарт. Пользовательский accent должен иметь отдельный признак override (сохранённое значение default само по себе не override). При отключении возвращается предыдущий источник; менеджер показывает, чей вклад перекрыт. Для v1 сохраняется прежний порядок групп; различие приоритета desktop/Android устраняется общим вычислением effective theme. Глобальные цвета текста/фона плагины не задают.

Карточка менеджера: название, описание PlainText, id/API/версия, состояние с причиной, разрешения, настройки, вклад в тему, обновление из файла, включение/отключение, удаление. На Android исправить profile-панели (сейчас выводятся только home) и убрать ручное присваивание library для всех navigation actions: обе платформы вызывают общий типизированный dispatcher, затем платформенный обработчик navigationRequested(destination). Ошибки не теряются в единственном временном toast: lastError на карточке с возможностью очистить; журнал до 20 записей на пакет без токенов, URI установки и данных профиля.

## Реализация и проверка этапа 3

Последовательные логические группы, релевантные тесты после каждой; один итоговый проверенный коммит этапа по исходному правилу пользователя:

1. Типизированный парсер v2, строгая валидация и лимиты, адаптер v1, реестр/миграция. Тесты границ размеров/глубины/типов/дубликатов, повреждённого реестра, отказа записи и повторного запуска.
2. Dependency graph, permissions, lifecycle и транзакционное обновление. Тесты циклов, диапазонов, отзыва разрешений, отключения зависимых, сохранения и восстановления settings/data, устаревших заданий.
3. Dispatcher, события, таймеры и правила. Fake player/clock; тесты запретов без полномочий, logout, rate limits, циклов событий, недоступного seek, отсутствия подписок после disable и корректной обратной связи. Без реальных ожиданий на минуты.
4. Общие UI-вклады, менеджер, платформенная навигация, content URI. QML-тесты home/profile/player на широком/узком экране, PlainText, конфликты темы. Android instrumentation: provider с неизвестной длиной, отозванный grant, превышение размера и повторный импорт; без устройства фиксировать непроверенное, не объявлять поддержку проверенной.
5. Полезные рабочие примеры: таймер сна; панель управления очередью (next/previous); тема с независимыми настройками. Каждый пример устанавливается и проверяется тестом; неподдержанные возможности не рекламируются. Документацию пользователя/API обновлять только по реализованному поведению.
6. Контрольный этап: debug, CTest, мобильный preview, доступная Android-сборка; на доступных Windows/macOS/Android — установка, обновление без потери настроек, отключение, перезапуск и удаление. Недоступные платформенные проверки перечислить явно.

Условия готовности: каждая принятая возможность имеет рабочий маршрут UI→host→результат и релевантный тест; код из пакетов нигде не исполняется; UI не обещает executable runtime, магазин или автоматическое обновление. Если отдельная функция не реализована, её документ/пример и возможность принять такой манифест должны быть исключены до завершения.
